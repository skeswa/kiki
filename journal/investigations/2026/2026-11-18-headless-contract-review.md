# Can a script complete the headless workflow in the reference book?

Reviewed on 2026-11-18. The starting point was the local [D-0009 design](../../decisions/0009-operate-headless-with-a-configurable-automation-policy.md) on top of `ae20a2e8`. This was a contract review. The checkout has a placeholder application and no runnable kiki daemon.

| Scenario                              | Finding from tracing the original contract                                                                                              | Current contract                                                                                                                                                                                                             |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Set up a host                         | Several chapters called first run an approval. A later install change had no method or journal.                                         | First install is local. Enrollment and registration are separate. Installation changes have an authenticated [bootstrap call](../../../docs/reference/book/13-architecture/grpc.md#changing-the-daemon-installation).        |
| Start Codex unattended                | The adapter mentioned launch arguments, but the configuration chapter gave no key or example.                                           | The operator sets [per-harness arguments](../../../docs/reference/book/11-configuration.md#sections). The local Codex 0.169.1 help lists the two flags and values in the example. The managed-launch proof still has to run. |
| Ask for more work                     | The only caller-supplied prompt was the first one. A terminal input reply could not identify a user turn.                               | [Follow-up prompts](../../../docs/reference/book/09-commands.md#kk-prompt) require a receipt from the addressed harness incarnation.                                                                                         |
| Resume after dirty-workspace recovery | Cascade required a choice, but the repair table had no plan for it. Exhausted delivery also still said a human had to act.              | [Recovery selection](../../../docs/reference/book/05-cascade.md#recovery-steps) uses a commit id. Exhaustion has separate retry and discard plans.                                                                           |
| Check who can approve                 | Several passages excluded the wildcard from thread callers. Some wildcard examples also implied that setup could be approved by a rule. | [Authority](../../../docs/reference/book/04-authority.md#automation-policy) matches the credential presented and defines which operations accept policy approval.                                                            |
| Grant provider consent                | The evaluator lacked the provider input. The consent table required a presenter even for a policy grant.                                | A [consent grant](../../../docs/reference/book/06-transcript.md#provider-egress-consent) identifies its presenter or policy approval and binds the provider, purpose, and disclosure version.                                |

To repeat the review, start with the [invariants](../../../docs/reference/book/02-invariants.md), then trace each scenario from the command through authority, RPC, SQLite, and its acceptance test. Check both the unattended outcome and the refusal case. Run `mise run check` to check formatting, links, contract terms, and the documentation build.

The [platform survival tests](../../../docs/reference/book/14-testing.md) still need a real kiki daemon and live agents. A passing documentation build does not qualify a supervisor or an SSH-only macOS host.
